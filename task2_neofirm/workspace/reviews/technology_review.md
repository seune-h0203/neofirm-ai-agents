## Detailed Findings

### technical_feasibility: 4/5 (STRONG)
NeoFirm이 AI에게 맡기려는 업무들을 기술적 관점에서 평가한다:

**달성 가능한 AI 업무들** [SOURCE] (E04):
- **학생 데이터 수집·분석:** 성적·학생부 데이터 구조화는 표준 데이터 파이프라인 문제. 현재 기술로 충분히 가능.
- **대학·전형 비교 자동화:** 정형화된 정보(모집정원, 전형방법, 최저등급)의 비교/매핑은 LLM+구조화 데이터로 처리 가능.
- **지원 가능성 분석:** 내신 등급 분포 + 학교별 입결 데이터를 결합한 확률 계산은 ML 회귀 모델로 가능.
- **수시 6장 후보군 생성:** 학생 프로파일 기반 순위화는 추천 시스템 문제. 현재 LLM 기반 추천 기술로 구현 가능.
- **변화 모니터링:** 성적 업데이트 감지 후 재분석 트리거는 표준 파이프라인 문제.
- **전략 시뮬레이션:** "A대학 대신 B대학 넣으면 어떻게 되나?" — 파라미터 변화에 따른 시나리오 비교는 현재 LLM으로 처리 가능.

단, **도메인 특화 학습이 필요** [ASSUMPTION] (E15): 수시 6장 후보군 AI 생성 품질이 전문가 판단 대비 충분한지는 미검증. 입시 특화 훈련 데이터 없이 일반 LLM만으로는 정교한 전략 생성이 어려울 수 있다.

### execution_feasibility: 1/5 (WEAK)
이것이 이 투자 건의 기술적 핵심 약점이다.

- **팀 없음** [ASSUMPTION] (E14): 소스 어디에도 AI 엔지니어, 입시 도메인 전문가, 데이터 사이언티스트의 존재가 확인되지 않는다.
- **프로토타입 없음**: 수시 6장 후보군을 실제로 생성해본 AI 시스템이 없다.
- **도메인 훈련 데이터 없음**: 입시 특화 LLM 훈련을 위한 학생 데이터·합불 결과 데이터가 없다.
- **전문가 파트너 미확보** [ASSUMPTION] (E14): 하이브리드 모델의 "전문가" 파트를 담당할 입시 컨설턴트가 온보딩되어 있지 않다.

NeoFirm 모델의 핵심은 기술(AI)과 도메인(입시)의 결합인데, 이 두 가지 모두 확인되지 않는다. 아이디어에서 작동하는 시스템까지의 거리가 매우 크다.

### differentiation: 4/5 (STRONG)
기술적 관점에서 데이터 플라이휠은 실제 moat이 될 수 있다:

**플라이휠의 기술적 타당성** [SOURCE] (E08, E09):
- 학생 프로파일 데이터 × 전문가 판단 기록 × 실제 합불 결과 = 세 레이어의 훈련 데이터
- 이 데이터로 fine-tuning된 입시 특화 모델은 일반 LLM이 복제할 수 없다
- 전문가의 수정 패턴(어디서 AI 추천을 바꿨는가)이 가장 희귀하고 가치 있는 데이터

**기술적 Moat 조건:**
- 최소 100~200건의 실제 지원 결과 축적 후 플라이휠 효과 발생 (Early Stage의 핵심 과제)
- 그 전까지는 AI 품질이 일반 LLM과 크게 다르지 않을 수 있음 [ASSUMPTION]

**경쟁 위협:**
- 대형 에듀테크 기업(메가스터디 등)이 같은 구조를 도입할 수 있음
- 단, 전문가 판단 데이터를 체계적으로 수집·정제하는 것은 NeoFirm이 선점하면 장벽이 됨

### scalability: 4/5 (STRONG)
AI + 전문가 역할 분리 설계가 기술적으로 올바른 확장성 구조다:

**확장성 분석** [SOURCE] (E04, E05):
- AI가 담당하는 데이터 처리·분석·후보군 생성은 선형 비용 없이 확장 가능
- 전문가는 최종 판단·상담만 담당 → 전문가 1인당 담당 학생 수가 기존 1:1 모델 대비 대폭 증가 가능

**병목 가능성 [ASSUMPTION]:**
- 입시 시즌은 극도로 집중적 (8월-11월 수시 집중) — 피크 타임 전문가 과부하 리스크
- AI 결과 검토에 드는 전문가 시간이 예상보다 길면 확장성이 제한될 수 있음

### evidence_quality: 2/5 (BELOW THRESHOLD)
기술 검증 관점에서 소스는 아이디어 제안서 수준이다:

- **없는 것들:** AI 프로토타입, 벤치마크, 입시 도메인 성능 검증, 학생 데이터 파이프라인 설계, 전문가 인터페이스 설계
- **있는 것들:** AI 업무 목록 설명 (E04), 플라이휠 개념 설명 (E08, E09)

기술 주장들은 논리적으로 타당하지만 어떤 것도 실제로 구현되거나 테스트되지 않았다.

## Provisional Decision

**HOLD**
**Confidence:** HIGH

**Rationale:**
기술적 아이디어는 매우 타당하다. AI + 전문가 하이브리드가 교육 컨설팅에서 실제로 작동할 수 있다는 것은 기술적으로 명확하다. 데이터 플라이휠도 설계가 올바르다.

그러나 execution_feasibility가 1점이다. **설계 문서가 있는 것과 작동하는 시스템이 있는 것은 완전히 다른 이야기다.**

입시 AI의 가장 어려운 부분은 "내신 4.2등급 학생이 연세대 경영학과 수시에 지원해야 하는가"라는 판단을 AI가 어떻게 지원하는가다. 이것을 해결할 팀과 데이터가 확인되어야 투자가 정당화된다.

**Upgrade to INVEST:** AI 엔지니어 + 입시 도메인 전문가 팀 구성 확인 + 10건 이상 파일럿으로 AI 생성 수시 전략의 품질 검증
